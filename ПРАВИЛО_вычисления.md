# ПРАВИЛО · где живут вычисления
### v1.0 · 21.08.2026 · STRK ENGINE

---

## Формулировка

> **Браузер не считает. Браузер рисует.**
>
> Любое число, влияющее на решение, вычисляется в Python, записывается
> в JSON и коммитится в репозиторий. `index.html` берёт готовое
> и отображает.

---

## Почему

Число, посчитанное в браузере:

- **нигде не сохраняется** — через неделю невозможно узнать, что система
  показывала вчера, а значит нельзя проверить, была ли она права
- **не прогоняется по истории** — бэктест не умеет открывать браузер
  и кликать на актив
- **расходится с сервером** — если логика в двух местах, однажды они
  разойдутся молча

Последнее случилось буквально: после подключения Volume Profile
серверный движок срезал LINK до 23%, а браузерный остался на 33%.
Два числа на одном экране, оба выглядят авторитетно. Пришлось убирать
браузерный блок.

---

## Как это выглядит на практике

```
СБОР               ВЫЧИСЛЕНИЕ           ХРАНЕНИЕ          ОТОБРАЖЕНИЕ
────               ──────────           ────────          ───────────
Dune, HL, OKX  →   Python-модули   →   data/cache/*.json  →  index.html
Hive, Surf         26 job                 в git                читает
FRED, CoinGecko    0 браузера          проверяемо           и рисует
```

**Кто считает:**

| Что | Модуль | Файл |
|---|---|---|
| Фаза Wyckoff | `token_scan_collector.py` | `token_scan/*.json` |
| Ускорение потока | `phase_analyzer.py` | `phase_analysis.json` |
| Уровни объёма и цели | `volume_profile_collector.py` | `volume_profile.json` |
| Агрессия покупателей | `cvd_multi_collector.py` | `cvd_multi.json` |
| Перекос деривативов | `hl_perps_collector.py` | `hl_perps.json` |
| Режим рынка | `market_regime.py` | `market_regime.json` |
| **Решение** | `decision_engine.py` | `decisions.json` |
| **Шкала лонг/шорт** | `asset_compass.py` | `asset_compass.json` |
| Сверка сделок | `trade_journal.py` | `trade_journal.json` |

**Что делает браузер:** читает эти файлы, раскрашивает, расставляет
по блокам. Ничего не выводит заново.

---

## Разрешённые исключения

Браузеру можно:

- **форматировать** — `$11.38` вместо `11.3801`, `+24.5%` вместо `0.245`
- **считать возраст** — «12 минут назад» из метки времени
- **выбирать цвет** по готовому коду (`ACCEL_UP` → зелёный)
- **позиционировать** — маркер на шкале из готового балла

Общий признак: если убрать эту операцию, смысл не изменится — изменится
только читаемость. Это отображение.

Браузеру **нельзя**:

- складывать сигналы в вердикт
- решать, что важнее
- выводить фазу, режим, размер позиции
- применять пороги

Общий признак: результат влияет на то, что человек сделает. Это решение,
и оно должно быть записано.

## Текущие нарушения · план устранения

На 21.08.2026 в `index.html` осталось:

```
flowRead            19 использований · читает фазу потока
conflicts.push       8 · детектор противоречий
buildDecision        2 · старый автор решения (вставка отключена)
buildInvalidations   1 · строит условия отмены
```

Всё это дублирует уже работающие серверные модули:

```
flowRead           → phase_analyzer.py  →  phase_analysis.json
conflicts          → decision_engine.py →  decisions.json.conflicts
buildDecision      → decision_engine.py →  decisions.json
buildInvalidations → decision_engine.py →  decisions.json.invalidations
```

**Устраняется отдельным заходом**, не вместе с добавлением новых блоков.
Причина: 19 использований `flowRead` — это половина модалки, и менять
её одновременно с добавлением компаса значит не понять, что именно
сломалось, если сломается.

## Проверка при каждом изменении

Перед тем как добавить что-то в `index.html`, вопрос:

**«Если я уберу этот расчёт из браузера — какое число пропадёт?»**

Если пропадёт число, влияющее на решение — расчёт должен быть в Python.
Если пропадёт только форматирование — можно оставить.
