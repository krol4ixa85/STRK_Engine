НАЗНАЧЕНИЕ:

Вычислить вероятность каждого свинг-сценария из TRADING MAP
на 5-дневный горизонт. Вероятности должны быть выведены из
УЖЕ существующих компонентов движка, а не «оценены на глаз».

Ключевая цель: дать пользователю честный ответ на вопрос
«какой из сценариев более вероятен?» с прозрачным разбором.

═══════════════════════════════════════════════════════════════════

ПРИНЦИПЫ (высшего приоритета):

1. Вероятности НЕ ВЫДУМЫВАЮТСЯ. Каждый фактор берётся из уже
   существующих компонентов (SCENARIO, CONFLICT, WATCHERS,
   STRUCTURE, PLAYBOOK_FLOW, HL Squeeze module).

2. Разбор ВСЕГДА показывается пользователю (не только итоговое
   число). Пользователь должен видеть, ПОЧЕМУ P = X%.

3. Метка [ГИПОТЕЗА] обязательна для всех итоговых вероятностей
   до накопления ≥15 закрытых прогнозов для калибровки.

4. EV (expected value) считается для каждого сценария —
   P × R/R − (1-P) × 1R. Отрицательный EV = вход математически
   не окупается.

5. Base priors будут пересчитаны на основании FORWARDTEST_LOG
   после ≥15 записей (сейчас: R71-R75 = 4 PENDING + 1 MISS).

═══════════════════════════════════════════════════════════════════

INPUTS:

Из уже посчитанных блоков LIQ/RUN:
  · SCENARIO NEED_SCORE (30-90 дн context)
  · CONFLICT_GATE (bull_count, bear_count)
  · CYCLE_BTC (UP / NEUTRAL / DOWN)
  · REGIME (5 состояний)
  · WATCHERS active levels
  · PLAYBOOK_FLOW class
  · FUEL_SIDE + TRADER_QUALITY (из squeeze_hl)
  · STRUCTURE positional (расстояние до VAL/VAH)
  · Все ключевые триггерные уровни из TRADING MAP

═══════════════════════════════════════════════════════════════════

ФОРМУЛА:

Для каждого сценария S ∈ {A, B, C, D}:

  P_raw(S) = Base_prior(S) × Prior_mod × Trigger_prox(S) × Conditions_match(S)

  P_normalized(S) = P_raw(S) / Σ P_raw(all scenarios) × 100%

  EV(S) = P × R/R − (1-P) × 1R

═══════════════════════════════════════════════════════════════════

СОСТАВЛЯЮЩИЕ ФОРМУЛЫ:

┌────────────────────────────────────────────────────────────────┐
│ 1. BASE PRIORS (baseline вероятности каждого сценария)         │
└────────────────────────────────────────────────────────────────┘

  A · LONG SAFE:        0.25
  B · LONG AGGRESSIVE:  0.20
  C · SHORT:            0.20
  D · DRIFT:            0.35

Итого: 1.00 (сумма = 1). Baseline подобрана эмпирически:
· LONG SAFE — типовой setup, но требует чётких условий
· LONG AGG — оппортунистический fake breakdown
· SHORT — базово менее вероятен в bull-cycle крипто
· DRIFT — самый частый исход в volatile regime

CALIBRATION: пересчёт после ≥15 закрытых прогнозов
(HIT/MISS statistics по типу сценария).

┌────────────────────────────────────────────────────────────────┐
│ 2. PRIOR MOD (модификатор от SCENARIO NEED_SCORE)              │
└────────────────────────────────────────────────────────────────┘

  NEED_SCORE > +15:
    bull priors × 1.5, bear × 0.5, drift × 1.0
  NEED_SCORE в (+5, +15]:
    bull × 1.2, bear × 0.8, drift × 1.0
  NEED_SCORE в [-5, +5]:
    все × 1.0 (baseline)
  NEED_SCORE в [-15, -5):
    bull × 0.8, bear × 1.2, drift × 1.0
  NEED_SCORE < -15:
    bull × 0.5, bear × 1.5, drift × 1.0

Классификация:
  · A и B → bull
  · C → bear
  · D → drift

┌────────────────────────────────────────────────────────────────┐
│ 3. TRIGGER PROXIMITY                                           │
└────────────────────────────────────────────────────────────────┘

Дистанция от текущей цены до триггера в %:

  |dist| < 3%     →  1.0
  3-8%            →  0.8
  8-15%           →  0.5
  >15%            →  0.3

Для DRIFT (D) — нет триггера, используется 1.0.

┌────────────────────────────────────────────────────────────────┐
│ 4. CONDITIONS MATCH (компоненты поддерживают сценарий?)        │
└────────────────────────────────────────────────────────────────┘

Каждый компонент вносит мультипликативный фактор.
Финальный factor клипается в диапазоне [0.4, 1.5].

Начальное значение factor = 1.0. Далее применяются модификаторы:

--- Для Сценария A (LONG SAFE от VAL bounce) ---

CYCLE_BTC:
  UP        → × 1.3
  NEUTRAL   → × 1.0
  DOWN      → × 0.6

REGIME:
  trending_up   → × 1.4
  ranging       → × 1.1
  quiet         → × 1.0
  volatile      → × 0.7 (шум съедает setup)
  trending_down → × 0.5

CONFLICT bull vs bear:
  bull ≥ bear   → × 1.2
  bull < bear   → × 0.7

PLAYBOOK_FLOW:
  distribution_decay → × 1.1
  distribution       → × 0.6
  accumulation       → × 1.2
  rebalance/other    → × 1.0

--- Для Сценария B (LONG AGGRESSIVE от liq bounce) ---

REGIME:
  volatile      → × 1.3 (шум помогает fake breakdown)
  ranging       → × 0.9
  trending_down → × 0.4
  quiet         → × 0.8

PLAYBOOK_FLOW:
  distribution_decay → × 1.2
  distribution       → × 0.5
  rebalance          → × 1.0

FUEL_SIDE:
  LONG_CASCADE_DOWN → × 0.9 (каскад может пойти дальше)
  BALANCED          → × 1.0
  NONE              → × 1.1

TRADER_QUALITY:
  TRAPPED_LOSERS → × 1.1 (могут капитулировать, дать wick)
  SMART_MIX      → × 0.9 (умные не паникуют)
  NEUTRAL_MIX    → × 1.0

--- Для Сценария C (SHORT при VAL rejection) ---

CYCLE_BTC:
  DOWN      → × 1.3
  NEUTRAL   → × 1.0
  UP        → × 0.5

REGIME:
  trending_down → × 1.4
  volatile      → × 1.1
  ranging       → × 1.0
  trending_up   → × 0.4

CONFLICT bear vs bull:
  bear > bull   → × 1.2
  bear ≤ bull   → × 0.7

FUNDING (negative funding уменьшает short profit):
  funding < -15% годовых → × 0.9 (штраф)
  funding в [-15%, +15%] → × 1.0
  funding > +15%         → × 1.1 (шорты бесплатны)

PLAYBOOK_FLOW:
  distribution_decay → × 0.8 (bearish flow слабеет)
  distribution       → × 1.3

--- Для Сценария D (DRIFT) ---

REGIME:
  volatile      → × 1.3 (много wick'ов, но не пробой)
  ranging       → × 1.2
  quiet         → × 1.0
  trending_*    → × 0.7 (тренд ломает диапазон)

═══════════════════════════════════════════════════════════════════

EV CALCULATION (expected value):

Для каждого активного сценария (A, B, C):

  EV = P_normalized × R/R − (1 − P_normalized) × 1R

Типовые R/R из TRADING MAP:
  A · LONG SAFE:       3.0 (stop 5%, T2 15%)
  B · LONG AGGRESSIVE: 3.0 (stop 5.5%, T2 22%)
  C · SHORT:           2.5 (stop 6.5%, T2 18%, минус funding cost)

Для D · DRIFT: EV = 0R (нет позиции)

Интерпретация EV:
  EV > +0.5R      → сильный setup, вход оправдан
  EV +0.0 to +0.5 → маргинальный, входить при подтверждении
  EV -0.3 to 0.0  → близко к break-even, не рекомендуется
  EV < -0.3R      → отрицательный, вход математически не окупается

═══════════════════════════════════════════════════════════════════

DECISION HANDSHAKE:

Итоговый DECISION должен учитывать вероятности:

  NEW_ENTRY = YES только если:
    · CONFLICT снят (bull ≠ bear ± 1)
    · P(scenario) ≥ 15%
    · EV(scenario) > +0.3R
    · WATCHERS L3 отсутствуют (или сняты)

  NEW_ENTRY = NO обосновывается через EV:
    "Все свинг-EV отрицательные: A=X.XR · B=Y.YR · C=Z.ZR"
    Это математический аргумент, не «на глаз».

═══════════════════════════════════════════════════════════════════

OUTPUTS:

В отчёт добавляется блок PROBABILITY MODULE после CONFLICT_GATE,
перед TRADING MAP:

  🎲 PROBABILITY MODULE · вероятности свинг-сценариев (5 дней)

  1. Formula explainer (какие компоненты используются)
  2. Ranking table (сценарии по вероятности)
  3. Разбор каждого сценария:
     · Base prior · Prior mod · Trigger prox · Conditions · итог
     · EV расчёт с интерпретацией
  4. Key insight (что это означает для DECISION)

═══════════════════════════════════════════════════════════════════

GATES:

При добавлении в CONFLICT_GATE:
  · Если EV(наилучший сценарий) > +0.3R → +1 bull или bear в стек
  · Если EV(все) < -0.3R → +1 в drift/D scenario (подтверждение FLAT)

═══════════════════════════════════════════════════════════════════

TRAPS:

⛔ НЕ показывать голые вероятности без разбора компонентов.
   Пользователь должен видеть P × R/R = EV.
⛔ НЕ округлять до целых до нормализации (потеря точности).
⛔ НЕ забывать [ГИПОТЕЗА] метку до калибровки.
⛔ НЕ использовать эти вероятности как автоматический сигнал
   входа. DECISION остаётся единственным местом торговой логики.
⛔ Base priors 0.25/0.20/0.20/0.35 — subjective, требуют
   калибровки на ≥15 закрытых прогнозах.
⛔ R/R = 3.0 для A/B и 2.5 для C — эмпирика из STRK VP,
   может измениться при пересчёте VP.
⛔ Conditions match коэффициенты — subjective, но выведены
   из уже существующей логики (skills/regime + squeeze_hl +
   CONFLICT_GATE).
