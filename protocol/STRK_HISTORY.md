### 7.1 · Решение от 25.07.2026: nansen-nexus исключён, используется только Nansen

```
РЕШЕНИЕ ПОЛЬЗОВАТЕЛЯ (не временная мера, не «пока не переподключится»):
nansen-nexus выведен из пайплайна STRK Engine насовсем.
Везде далее по проекту читать «nansen-nexus» как «Nansen (официальный)».

ЧТО МЕНЯЕТСЯ ОПЕРАЦИОННО

Блок «Когорты и Flow Map» (STRK_BLOCK_SKILLS.md, Ярус 4):
  было      nansen-nexus network-traversal (происхождение + First Funder)
  стало     Nansen address_related_addresses (цепочка фондера)
          + Nansen address_counterparties (топ контрагентов по взаимодействию)
          + Nansen address_transactions (последние транзакции адреса)
  ПОСЛЕДСТВИЕ  этапы 3 (происхождение) и 4 (назначение L2) Flow Map теперь
               собираются вручную, по шагам через несколько вызовов Nansen,
               а не одним автоматизированным traversal-вызовом. Дольше,
               но не менее надёжно — просто больше явных шагов агента.

Блок «Классификация кошельков» (STRK_BLOCK_SKILLS.md) — БЕЗ ИЗМЕНЕНИЙ:
  факторизация First Funder уже была построена на address_related_addresses,
  то есть на обычном Nansen, а не на nansen-nexus. Ничего не сломано.

ЧТО НЕ МЕНЯЕТСЯ
  реестр опровергнутого, ВЕТО стадий 3–4 над 1–2, семь ловушек классификации —
  методология та же, поменялся только инструмент получения данных для 2 стадий.

СЛЕДСТВИЕ ДЛЯ ЧЕКЛИСТА §6
  строку «не звонить в … Nansen whale-tools по STRK» это не отменяет —
  whale/smart_trader/top_pnl остаются в реестре отклонённого (нули по STRK),
  речь только про address_related_addresses / address_counterparties /
  address_transactions / token_flows / token_who_bought_sold.
```

