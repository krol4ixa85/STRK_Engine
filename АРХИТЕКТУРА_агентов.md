## Роли агентов · кто чем занят

Разложил 54 скрипта `composite` плюс отдельные job по ролям.

### СБОРЩИКИ — приносят сырьё

```
run_all_collectors · dune_collector · dune_sector_collector
alt_cycle_collector · defillama_collector · funding_collector
stables_collector · whale_holdings_collector · ekubo_flow
endur_lst_flow · native_staking_flow · hive_price_collector
hive_health_collector · funding_per_token · news_impact_v5
macro_narratives · total_phase · token_scan_collector
strk_avnu_collector
```

Ничего не решают. Только тянут данные и кладут в `data/cache/`.

### ДЕТЕКТОРЫ — превращают сырьё в признаки

```
wyckoff_phase · composite_detector_v2 · technical_momentum
cex_flow · cex_flow_alert · liquidity_shift · bridge_activity
effort_result · cvd_analysis · cross_token_correlation
concentration_metrics · event_calendar · event_layer
news_aggregator · squeeze_detector · covert_flow_detector
cross_window_pattern · auto_discovery · dynamic_exit_signals
```

Девятнадцать штук. Каждый отвечает за свой признак и честно молчит,
когда данных нет.

### РЕШАЮЩИЕ — раньше их было несколько, теперь один

```
confluence_gate          → композитный сигнал из 9 факторов
decision_layer           → LIQ-контракт по STRK
interpretation_layer ×2  → unified reading + паттерны Wyckoff
market_regime            → взвешенный режим рынка
decision_engine          → ★ единственный автор действия
```

**Здесь была главная проблема.** Несколько скриптов отвечали на вопрос
«что делать», каждый по-своему, и никто не сводил их вместе. `MASTER §0.28
SINGLE BRAIN` требует единственного источника `final_action` — до сих пор
это требование не выполнялось.

`decision_engine.py` читает выводы всех остальных и выдаёт **одно действие
с размером**. Остальные становятся входами, а не конкурентами.

## Как течёт решение

```
СБОР                    ДЕТЕКТОРЫ              РЕШЕНИЕ
────                    ─────────              ───────
Dune ──────┐
CoinGecko ─┤            wyckoff_phase ─┐
Hive ──────┼─→ cache ─→ confluence ────┼─→ decision_engine ─→ decisions.json
OKX ───────┤            cex_flow ──────┤        │
Surf/RSS ──┤            market_regime ─┤        │
FRED ──────┘            unified ───────┘        │
                                                ▼
                                        decision_log.jsonl
                                                │
                                    (ждём 7 дней)
                                                ▼
                                     decision_engine --verify
                                                │
                                                ▼
                                     decision_accuracy.json
                                                │
                                    (при N ≥ 20 на правило)
                                                ▼
                                     подстройка порогов
```

Контур замкнулся. До сих пор стрелка от решения к проверке отсутствовала:
решение жило в JavaScript в браузере, нигде не сохранялось и потому не
могло быть проверено.

## Чего ещё нет

**Агента-улучшателя.** Он должен читать `decision_accuracy.json` и
предлагать изменения порогов. Строить его сейчас бессмысленно: нечего
улучшать, пока нет ни одного закрытого решения. Появится после того, как
накопится 20+ закрытых на правило — примерно через два месяца при
четырёх прогонах в сутки.

**Автоматической отмены правил.** Если правило показывает точность ниже
случайной, оно должно отключаться само. Тот же срок.

**Единой шины событий.** Сейчас агенты общаются через файлы в `data/cache/`.
Для нынешнего масштаба это нормально и даже удобно — всё видно в git.
Менять стоит только если появится потребность в реакции быстрее минуты.

---

## Правило, которое стоит держать

> Решение принимается в Python, записывается в файл, и только потом
> показывается. Всё, что считается в браузере, не может быть проверено,
> а значит не может быть улучшено.

Это ровно то, обо что споткнулась первая версия блока решений.
